文档性质：增量实现方案（在现有主线之上新增盘点「发现」层）
依据文档：docs/配件资产管理系统_设计文档_v1.md 第 4.7 节、第 6.4 节
主线约束：现有入库/装机/拆下/借出/归还代码与测试必须保持不变且继续全绿


〇、最高原则（不得违反）
--------------------------------------------------------------------------------
1. 不许破坏现有主线。改动仅限新增盘点相关文件/表/接口/页面，以及本文第六节
   允许的两处小修。交付前必须跑通全部既有测试。

2. 盘点是纯读发现层：全程不得修改 part 状态、不得写入 movement_log。
   盘点只负责「发现并登记差异」；差异后续处置（校正/补录/上报）本次不做。
   这是本模块红线。


一、前提确认（已与需求方对齐）
--------------------------------------------------------------------------------
1. expected_* 只冻位置，不加显式状态列
   - 严格按设计文档 4.7：只冻 expected_loc_kind / expected_loc_id
   - 「应在状态」由位置派生展示：库位→在库、服务器→在用、外单位→借出/已调拨
   - 硬约束：派生状态仅用于展示，判定盘亏/盘盈/错位只看位置比对
   - 一句话：位置是唯一冻结基准，状态是它的只读投影

2. 盘盈记编号：明细增加可选 scanned_asset_no
   - 盘盈明细靠它自证「扫到了什么」；part_id 对盘盈可空
   - 现场件清点时也一律回填 scanned_asset_no（不只盘盈用），便于复核

3. 未清点明细
   - 初始 result = 「待复核」
   - 过程中允许部分未录
   - 结案校验：盘点单标「已完成」时，必须所有明细都不是「待复核」
     （允许过程漏录，不允许漏盘结案）

4. 在外借出件数据
   - 用主线借出流程造（发起借出→三级审批→借出）
   - 不改现有种子数据，不为盘点预置「凭空在外」的借出件

5. 「标记已完成」只改 stocktake.status，不碰 part / 履历
   - 配合结案前「明细必须盘全」校验一起做


二、本次范围：盘点「发现」全流程
--------------------------------------------------------------------------------
新增三张表（严格按设计文档 4.7）：
  - stocktake              盘点任务
  - stocktake_item         盘点明细
  - stocktake_discrepancy  差异处置单

流程：
  1) 发起盘点：选范围（demo 至少支持「全盘」；scope_kind 字段保留全部取值）
     发起时冻结快照：把当时范围内每个配件的应在位置拷贝进
     stocktake_item.expected_*。此后比对只认这份冻结拷贝，不再实时读 part。

  2) 逐件清点（本单位现场件）：
     盘点员手工录入固定资产编号（demo 代替扫码），系统对照冻结快照自动判定：
     相符 / 盘亏 / 盘盈 / 错位。

  3) 函证核对（expected_loc_kind = 外单位）：
     这些件必须出现在明细里，不得跳过；走函证支线——录入外单位反馈
     （在/不在）+ feedback_source。反馈「不在」→ 判为盘亏。
     未录函证反馈前不得判为「相符」。

  4) 盘盈（账无实有，按「查全表」定义）：
     录入的固定资产编号在系统 part 全表（按 fixed_asset_no）查无
     → 生成一条盘盈明细（part_id 可空，scanned_asset_no 必填）。
     注意：不是「不在本次快照明细中」——以免范围非全盘时把
     「账有但本次未纳入」误判为盘盈。

  5) 登记差异：
     所有非「相符」结果写入 stocktake_discrepancy。
     盘亏差异单状态强制置「挂起追查」。

  6) 查看结果 + 结案：
     汇总（相符/盘亏/盘盈/错位/待复核数量）+ 差异清单；
     结案仅改 stocktake.status，且要求明细全部已盘。


三、盘点不变量（务必实现）
--------------------------------------------------------------------------------
1. 快照基准：比对只认发起时冻结进 stocktake_item.expected_* 的值，不实时读 part。
2. 只发现不修正：盘点全流程不得写 movement_log、不得改 part.current_status/current_loc_*。
3. 盘盈盘亏禁止对冲：不提供任何把盘亏与盘盈相互抵消/归零的操作；
   盘亏差异单不得被「配上一笔盘盈」就自动置为已处置。
4. 盘亏强制挂起：盘亏差异单状态为「挂起追查」；
   不存在能让它自动核销/报废/对冲的代码路径。
5. 在外件不得跳过：范围内 expected_loc_kind=外单位 的件必须生成明细，
   且在获得函证反馈前不得被判为「相符」。
6. 结案必须盘全：存在「待复核」明细时禁止标「已完成」。
7. 判定不看派生状态：check / 函证逻辑只比位置；派生状态仅 schema/UI 展示字段。


四、新增 ORM 模型（字段）
--------------------------------------------------------------------------------

--- Stocktake（盘点任务）---
id                PK
scope_kind        str     全盘 / 按机房 / 按责任组 / 按配件类型 / 指定清单
                          （demo UI 仅发起全盘；字段留全）
scope_value       JSON/str, 可选   非全盘时的范围取值；全盘可空
initiator_id      FK → user
initiated_at      datetime
snapshot_at       datetime         账面快照冻结时间
status            str              进行中 / 已完成 / 已归档

--- StocktakeItem（盘点明细）---
id                PK
stocktake_id      FK → stocktake
part_id           FK → part, 可空  盘盈时可空
expected_loc_kind str, 可空        来自快照；盘盈无账时为空
expected_loc_id   int, 可空        来自快照；盘盈无账时为空
result            str              待复核 / 相符 / 盘亏 / 盘盈 / 错位
actual_loc_kind   str, 可空
actual_loc_id     int, 可空
scanned_asset_no  str, 可空        现场录入固定资产编号；盘盈唯一身份线索
checker_id        FK → user, 可空
checked_at        datetime, 可空
feedback_source   str, 可空        函证核对：反馈来源

发起全盘时：对范围内每个 part 插一行，
  expected_* ← 当时 part.current_loc_*，
  result = 待复核。

--- StocktakeDiscrepancy（差异处置单）---
id                  PK
stocktake_item_id   FK → stocktake_item
discrepancy_type    str     盘亏 / 盘盈 / 错位
status              str     挂起追查 / 待复核 / 已处置
                            （本模块：盘亏强制「挂起追查」；
                             无接口将其改为「已处置」）
reviewer_id         FK, 可空     本模块不填
review_conclusion   文本, 可空   处置层留空
resolution          文本, 可空
linked_ref          字符串, 可空  后续关联审批/校正履历/上报单据


五、判定规则（只比位置，不看派生状态）
--------------------------------------------------------------------------------

【现场清点】（非外单位账内件，或新建盘盈）

情形 A：扫到编号对应本行 part，且 actual_loc == expected_loc
  → result = 相符；不写 discrepancy

情形 B：扫到编号对应本行 part，但位置不同
  → result = 错位；写 discrepancy(错位)

情形 C：账有（本行有 part），实报「找不到」
  → result = 盘亏；写 discrepancy(盘亏, status=挂起追查)

情形 D：扫到编号在系统 part 全表查无（查全表）
  → 新建盘盈明细（part_id 空，expected 空，scanned_asset_no=该号）
  → result = 盘盈；写 discrepancy(盘盈)

【POST /stocktakes/{id}/check 契约三分支（A，编码必须按此实现）】

分支 1 · 账内清点（报位置）
  入参：scanned_asset_no 必填 + actual_loc_kind/id
  解析：用 scanned_asset_no 在本盘点单明细中定位对应 part 的待盘/可复盘行
        （该编号必须能在系统 part 表查到，且属于本单明细）
  判定：只比 actual_loc 与该行 expected_loc
        相同 → 相符；不同 → 错位（写 discrepancy）
  回填：scanned_asset_no、actual_*、checker、checked_at、result

分支 2 · 账内报找不到（盘亏）
  入参：scanned_asset_no 或 item_id 定位明细 + missing=true
  判定：result=盘亏；写 discrepancy(盘亏, 挂起追查)
  不要求 actual_loc

分支 3 · 查全表无件（盘盈）
  入参：scanned_asset_no 必填（可带实际位置作备注性 actual_*）
  解析：系统 part 表按 fixed_asset_no 查无此编号
  判定：新建盘盈明细（part_id 空、expected 空）+ discrepancy(盘盈)

互斥与拒绝：
  - 编号在系统存在、但不在本盘点单明细中 → 400（范围外，非盘盈）
  - 外单位明细不得走 /check 报相符；外单位走 /confirm-external
  - 已结案盘点单拒绝再 check

【函证】（expected_loc_kind == 外单位）

反馈「在」：
  → result = 相符；actual = 外单位同 expected；feedback_source 必填

反馈「不在」：
  → result = 盘亏；feedback_source 必填；discrepancy(盘亏, 挂起追查)

未反馈：
  → 保持「待复核」；禁止标相符

【派生展示映射】（UI / 只读字段 only）
  库位 → 在库
  服务器 → 在用
  外单位 → 借出（demo；文档含已调拨，本模块无调拨数据）


六、API 端点列表
--------------------------------------------------------------------------------
前缀 /api；当前操作人请求头 X-Operator-Id。

POST   /stocktakes
       body: scope_kind（demo 用「全盘」）
       → 冻结快照，生成明细（result=待复核）

GET    /stocktakes
       → 盘点单列表

GET    /stocktakes/{id}
       → 详情 + 汇总计数（待复核/相符/盘亏/盘盈/错位）+ 明细摘要

GET    /stocktakes/{id}/items
       → 明细列表（含派生应在状态、是否外单位函证标记）

POST   /stocktakes/{id}/check
       现场清点（契约三分支，见第五节）：
       - 分支1：scanned_asset_no + actual_loc_* → 相符/错位
       - 分支2：scanned_asset_no|item_id + missing=true → 盘亏
       - 分支3：scanned_asset_no 在 part 全表查无 → 盘盈

POST   /stocktakes/{id}/confirm-external
       函证：
       - item_id
       - present: bool（在/不在）
       - feedback_source 必填

GET    /stocktakes/{id}/discrepancies
       → 差异清单（只读）

POST   /stocktakes/{id}/complete
       → 结案：全部明细非「待复核」则 status=已完成；否则 400
       → 只改 stocktake.status，不碰 part / 履历

明确不提供：
  - 盘盈盘亏对冲接口
  - 将盘亏差异单改为「已处置」的接口
  - 任何写 part / movement_log 的盘点接口

实现约束：
  services/stocktake.py 禁止调用 insert_movement /
  apply_projection_from_movement。

八、不变量 → 保障逻辑映射
--------------------------------------------------------------------------------
1. 快照基准
   → 发起时一次拷贝 expected_*；判定只读 item.expected_*，不读实时 part
   → 测试：发起后装机，expected_* 仍为旧值

2. 只发现不修正
   → stocktake 服务不碰 movement / part 投影
   → 测试：判盘亏后 part.current_status 不变、该 part 履历条数不变

3. 盈亏禁止对冲
   → 无对冲 API；两笔差异独立 INSERT
   → 测试：断言无对冲/自动已处置接口（或调用则 404/405）

4. 盘亏强制挂起
   → 写 discrepancy 时盘亏固定 status=挂起追查
   → 无改为已处置的代码路径

5. 在外不得跳过
   → 快照含外单位件；函证前 result=待复核；结案要求无待复核
   → 测试：主线借出造在外件 → 明细存在；未函证不可相符；不在→盘亏

6. 结案必须盘全
   → complete 校验无「待复核」明细
   → 测试：有待复核时 complete 失败；盘全后成功且不改 part

7. 判定不看派生状态
   → check / confirm-external 只比 loc；派生仅展示字段


九、必须覆盖的测试（pytest，新建 test_stocktake.py，勿改现有用例）
--------------------------------------------------------------------------------
1. 快照基准：发起盘点后把某在库件实时装机 → 该件 stocktake_item.expected_*
   仍为发起时的旧值，不随实时变化。

2. 只发现不写履历/不改 part：对某件判为盘亏后，该件 part.current_status 不变，
   且其 movement_log 记录数在盘点前后不变。

3. 盘亏强制挂起且不可对冲：盘亏差异单状态为「挂起追查」；
   不存在把盘亏+盘盈对冲或将盘亏自动置为已处置的接口/路径
   （以缺失该接口或显式拒绝断言）。

4. 在外件走函证不跳过：用主线借出造在外件；明细中存在；
   未录函证反馈时不得为「相符」；反馈「不在」→ 判为盘亏。

5. 结案守卫：有「待复核」时 complete 失败；
   盘全后成功且不改 part / 不增履历。

6. 红线静态断言（C）：断言 stocktake 服务模块未 import/暴露
   insert_movement、apply_projection_from_movement 等写履历/改投影入口
   （类似主线 assert_no_movement_mutation_api 的静态检查）。

7. 现有主线回归：运行全部既有测试（test_core_rules.py 等），确认仍全绿。

十二、Demo 简化 → 未来收口说明
--------------------------------------------------------------------------------
【只做发现】
现状：盘点只登记差异，不修正账本。
收口：处置层单独增量——
  错位 → 走现有 movement 服务新增「校正」事件（新增履历，不改历史）；
  盘盈 → 走入库入口补建档案；
  盘亏上报 → 对接内部资产损失制度。
  均不改变盘点「只读发现」的定位。

【手工录入代替扫码】
现状：手工填 scanned_asset_no。
收口：录入接口换成扫码枪/二维码输入即可，判定逻辑不变。

【仅演示全盘】
现状：UI 只发起全盘。
收口：scope_kind / scope_value 字段已留全；按机房/类型/清单只是查询范围不同，
  表结构不动。

【派生状态仅展示】
现状：不落 expected_status，判定只看位置。
收口：若业务日后确需冻结状态，再单独议；当前坚持「位置唯一冻结基准」。
